# Reusable Example

A Reusable artifact should provide enough evidence to support
`Available + Functional + Reusable`.

## Typical Evidence Pattern

- the artifact already satisfies the Functional boundary;
- the artifact defines a bounded transfer or reuse task;
- the transfer task uses the released artifact with no hidden author support;
- the reviewer can run that transfer route and inspect its output.

## What Makes This Stronger Than Functional

Reusable requires evidence that goes beyond a single representative workflow.
The key additional evidence is a concrete and reviewable reuse path, not a
general claim that the software could be adapted in principle.

## Common Boundary

A case is usually strong enough for Reusable when it includes a second input or
bounded scenario, a documented command for that scenario, and an expected
output or behavior that the reviewer can verify directly.
